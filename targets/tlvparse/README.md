# Target B: tlvparse

`tlvparse` is a small, independent C application used as the second target. It
parses a binary Type-Length-Value message from a file and prints the decoded
name and identifier.

## Wire format

A message is a sequence of records:

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | record type: `1` NAME, `2` ID, `3` END |
| 1 | 1 | value length (0-255) |
| 2 | `length` | value bytes |

* NAME is a string copied into a 32-byte buffer.
* ID is exactly 4 bytes, little-endian.
* END terminates the message.
* Unknown types and truncated records are invalid.

## Output contract

| Input | Exit | stdout | stderr |
|---|---:|---|---|
| Valid NAME and ID | 0 | `name=<name>\nid=<decimal>\n` | empty |
| Valid NAME only | 0 | `name=<name>\n` | empty |
| Invalid or truncated | 2 | empty | `invalid input\n` |
| Missing/unreadable file | 2 | empty | usage/cannot-open message |

## Versions

### `versions/base`

The vulnerable version. `parse_message` copies the one-byte NAME length
directly into `msg->name[32]`:

```c
memcpy(msg->name, data + offset, length);
```

A NAME of 200 bytes (`inputs/overflow-200.tlv`) produces an AddressSanitizer
`stack-buffer-overflow` in `parse_message`.

### `versions/correct`

Rejects a NAME whose length is greater than or equal to `NAME_CAP` (32) before
the copy. Both overflow inputs are rejected with exit code 2, and valid inputs
still parse.

### `versions/incomplete`

Rejects only lengths above 128:

```c
if (length > 128) {
    return -1;
}
```

The original 200-byte input is blocked, but the alternate 64-byte input
(`inputs/overflow-64.tlv`) still overflows the 32-byte buffer. This is the
intended `INCOMPLETE_FIX` scenario.

### `versions/regression`

Contains the correct bound check plus a functional regression: valid NAME
lengths greater than 8 are rejected. The valid 16-byte name and the 31-byte
boundary name now fail with exit code 2, while the overflow inputs are fixed.

## Inputs

Generated by `tools/make_inputs.py`:

| File | Purpose |
|---|---|
| `inputs/valid.tlv` | 16-byte NAME + ID |
| `inputs/boundary.tlv` | maximum valid 31-byte NAME + ID |
| `inputs/overflow-200.tlv` | original overflow (200-byte NAME) |
| `inputs/overflow-64.tlv` | alternate overflow (64-byte NAME) |
| `inputs/invalid-truncated.tlv` | declared length exceeds remaining input |
| `inputs/invalid-type.tlv` | unknown record type |

## Build

The manifest uses a direct `gcc` command with `{flags}` and hardening flags.
The harness supplies the release or sanitizer profile. No Makefile or
third-party dependency is required.

## Reference oracle

`reference-tests.json` defines the expected result per version. The expected
output strings are fixed by the output contract above, not by the patched
binary.

| Test | Base | Correct | Incomplete | Regression |
|---|---|---|---|---|
| `FUN-VALID` | pass | pass | pass | **fail** |
| `FUN-BOUNDARY` | pass | pass | pass | **fail** |
| `INV-TRUNCATED` | pass | pass | pass | pass |
| `INV-TYPE` | pass | pass | pass | pass |
| `SEC-ORIGINAL` | vulnerable | fixed | fixed | fixed |
| `SEC-ALTERNATE` | vulnerable | fixed | **vulnerable** | fixed |

## Expected scenario results

| Scenario | Patched version | Exit code | Statuses |
|---|---|---:|---|
| Correct patch | `versions/correct` | 0 | `FIXED` |
| Incomplete patch | `versions/incomplete` | 10 | `INCOMPLETE_FIX` |
| Regression patch | `versions/regression` | 20 | `FIXED`, `FUNCTIONAL_REGRESSION` |

Run one scenario:

```bash
PYTHONPATH=src python3 -m security_patch_validator.cli targets run \
  --target targets/tlvparse/target.json --scenario incomplete \
  --artifacts-dir artifacts/tlvparse-incomplete \
  --output reports/tlvparse-incomplete.json --pretty
```
